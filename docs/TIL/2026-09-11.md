# 2026-09-11 React Native 학습 정리

## 오늘 학습한 내용

1. **`FlatList`로 목록 렌더링 방식 개선**
   기존에 `todolist.map()`으로 직접 순회하며 렌더링하던 방식을 `FlatList`로 교체했다. `data`, `renderItem`, `keyExtractor`를 사용해 각 아이템을 그려주고, 화면에 보이는 만큼만 렌더링하는 가상화(virtualization) 방식이라는 점에서 `.map()`과 차이가 있다는 것을 확인했다.

2. **`Pressable`로 터치 인터랙션 구현**
   할일 아이템을 눌러서 삭제할 수 있도록 `Pressable`을 적용했다. `style` prop에 함수를 넘기면 `{ pressed }` 상태를 받아 눌린 동안에만 다른 스타일(`opacity` 조정)을 적용할 수 있다는 것을 학습했다.

3. **안드로이드/iOS 환경별로 다르게 동작하는 `Pressable`**
   `Pressable`의 `android_ripple` prop은 이름 그대로 안드로이드에서만 물결(ripple) 효과를 적용하고 iOS에서는 무시된다. 반면 `style`의 `pressed` 상태를 이용한 `opacity` 처리는 두 플랫폼 모두에 적용되므로, iOS에서도 눌렀을 때 시각적 피드백을 받을 수 있도록 두 방식을 함께 사용했다.

4. **`Modal`을 이용한 할일 입력 UI 분리**
   할일을 입력하는 `TextInput`과 버튼을 `Modal` 컴포넌트로 분리해서, 버튼을 눌렀을 때만 입력창이 나타나도록 구조를 변경했다.

5. **`Image`는 로컬 파일을 `require`로 불러온다**
   웹의 `<img src="...">`와 달리 RN의 `Image`는 로컬 에셋을 쓸 때 `source={{ uri: "..." }}`가 아니라 `source={require("../assets/image.webp")}` 형태로 정적 경로를 넘겨야 한다. `require`로 넘긴 경로는 번들러가 빌드 시점에 리소스로 포함시켜준다는 점을 확인했다.

6. **디버깅 방법 복습**
   기존 웹/앱 개발에서 쓰던 디버깅 습관(콘솔 로그 확인, 에러 스택 추적 등)을 RN 환경에도 그대로 적용해볼 수 있다는 것을 다시 확인했다.
